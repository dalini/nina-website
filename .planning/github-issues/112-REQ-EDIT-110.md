## Requirement

- **Statement**: When an Exhibition entry is first saved, the Editing Interface MUST set its slug from its title and the year of its start date (e.g. "Faltungen", 2025-12-01 → `faltungen-2025`), consisting only of lowercase letters, digits and hyphens, with umlauts and ß transliterated and every other character replaced by a hyphen; later edits of the title or the dates MUST NOT change the slug, and the form MUST NOT let editors change it after the first save.
- **Rationale**: The slug is the address of the entry's page (`/exhibitions/<slug>/`, FR-4.7); a slug that changed with the title would break links that curators, press and galleries already use.
- **Assumptions**: Sveltia CMS can build an entry's slug from the title and the start-date year when the entry is created and keeps it on later saves; this is verified at implementation, and if it cannot, the implementer stops and reports it, because the Site Build must not generate or change slugs (FR-4.7)
- **Out of Scope**: The other Exhibition entry fields and their required-field checks (REQ-EDIT-030); the slug's character rule in the Site Build (REQ-CONTENT-080); two entries with the same slug (REQ-CONTENT-090); a missing slug in the content (REQ-CONTENT-050).
- **Design Traceability**: N/A: the Sveltia CMS UI is used as is, without restyling (DESIGN.md Components)
- **Architecture Traceability**: Editing Interface (configuration in `dalini/nina-site`); Content Store (Exhibition slugs, set once)
- **Security Traceability**: SEC-INPUT-6

## Acceptance Criteria

1. **AC-01 — Expected behavior**: Given a signed-in test editor creates an Exhibition entry titled "Faltungen" starting 2025-12-01, when she saves it for the first time, then the commit gives it the slug `faltungen-2025`, and the built site has its page at `/exhibitions/faltungen-2025/` and `/de/ausstellungen/faltungen-2025/`.
2. **AC-02 — Boundary or failure behavior**: Given titles "gentle touch", "Kunst / Raum" and "../impressum" with a start date in 2024, when each entry is first saved, then each slug consists only of lowercase letters, digits and hyphens, ends with `-2024`, and contains no `/`, `.` or space.
3. **AC-03 — Boundary or failure behavior**: Given a title containing ä, ö, ü or ß, when the entry is first saved, then the slug contains only lowercase letters, digits and hyphens, and each of these letters is transliterated as decided in PQ-67.
4. **AC-04 — Prohibited behavior**: Given the saved entry `faltungen-2025`, when the editor changes its title to "Faltungen II" and its start date to 2026-01-15 and saves again, then the slug stays `faltungen-2025`, the page address does not change, and the form offers no way to edit the slug.

## Failure Behavior

- **On Invalid Input**: A title or start date missing at the first save is rejected by the required-field checks of REQ-EDIT-030 before any slug is set
- **On Authentication Failure**: Without a valid sign-in the Editing Interface saves nothing (REQ-AUTHN-010)
- **On Authorization Failure**: N/A: every signed-in editor may create entries (SEC-AUTHZ-1)
- **On Security-Decision Failure**: Deny by default: a slug the Site Build rejects fails the publish (REQ-CONTENT-080, REQ-CONTENT-090)
- **On External Dependency Failure**: GitHub unreachable: the save fails in the Editing Interface and nothing is committed
- **On System Error**: The save fails without a commit; the editor sees the CMS's error and can save again
- **Logging / Audit**: The commit records the editor and time (SEC-AUDIT-1)
- **Alerting**: N/A
